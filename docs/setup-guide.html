Cài đặt Growth Toolkit

Từ con số không đến một dashboard đang chạy: tạo bot Discord, mời bot vào server với đúng quyền, chạy website ở máy bạn, và cấp quyền đăng nhập cho tài khoản admin.

khoảng 15 phút cần Node.js 23.4+ cần quyền admin ở server Discord của bạn không cần domain hay hosting

Tổng quan

Có ba thứ cần khớp với nhau. Thiếu một là hỏng cả luồng:

Thành phầnLà gìCấu hình bằng
Bot Tài khoản bot đăng nội dung và gửi DM trong Discord DISCORD_TOKEN, HOME_GUILD_ID
Website Dashboard chạy ở máy bạn để soạn nội dung, phát panel, xem số liệu PORT, HOST, PUBLIC_BASE_URL
Tài khoản admin Discord ID được phép đăng nhập dashboard DASHBOARD_OWNER_IDS, SESSION_SECRET

Cả ba đều đọc từ một file .env duy nhất ở thư mục dự án. Sửa file đó thì phải khởi động lại — biến môi trường chỉ được đọc một lần lúc chạy.

1

Tạo bot Discord

  1. Mở Developer Portal → New Application → đặt tên (tên này hiện ra khi mời bot) → Create.
  2. Sang tab Bot → Reset Token → Copy. Đây là DISCORD_TOKEN. Token chỉ hiện đúng một lần; đóng trang là phải reset lại.
  3. Vẫn ở tab Bot, cuộn xuống Privileged Gateway Intents → bật Server Members Intent → Save Changes.
  4. Sang tab OAuth2 → copy Client ID (DISCORD_CLIENT_ID) và Client Secret (DISCORD_CLIENT_SECRET). Chưa thấy secret thì bấm Reset Secret.

Server Members Intent là bắt buộc. Không bật thì bot không nhận được sự kiện có người join, nên mất toàn bộ số liệu quy nguồn invite, và cũng không đếm được ai đang giữ role thông báo. Bot sẽ báo lỗi Used disallowed intents lúc khởi động nếu code cần intent mà Portal chưa bật.

Message Content Intent không cần bật — bot không đọc nội dung tin nhắn của ai. Nếu chỉ bạn dùng, nên tắt Public Bot ở tab Bot để không ai mời bot vào server khác được.

Token là mật khẩu của bot. Đừng commit, đừng dán vào chat, đừng chụp màn hình có nó. File .env đã nằm trong .gitignore. Lỡ lộ thì Reset Token ngay.

2

Khai redirect URI

Dashboard đăng nhập bằng Discord OAuth. Discord chỉ trả người dùng về những địa chỉ đã được khai trước, nên bước này không bỏ được.

  1. Developer Portal → tab OAuth2 → mục Redirects → Add Redirect.
  2. Dán đúng chuỗi dưới đây rồi bấm Save Changes:
http://localhost:3000/api/auth/callback

Chuỗi này bằng PUBLIC_BASE_URL cộng thêm /api/auth/callback. Nó phải giống từng ký tự:

  • Không thừa dấu / ở cuối.
  • Đổi PORT thì phải khai lại địa chỉ mới (ví dụ http://localhost:8080/api/auth/callback) và sửa PUBLIC_BASE_URL cho khớp.
  • localhost và 127.0.0.1 là hai chuỗi khác nhau với Discord. Khai cái nào thì mở dashboard bằng đúng cái đó.

Lệch một trong ba thứ trên là gặp Invalid OAuth2 redirect_uri. Lúc chạy, app cũng tự cảnh báo nếu PUBLIC_BASE_URL và PORT không khớp.

3

Mời bot vào server

Bot cần bộ quyền khác nhau ở hai loại server: server nhà (server bạn muốn kéo người vào) và server đối tác (nơi bạn được phép đăng panel).

QuyềnServer nhàĐối tácDùng để làm gì
View Channels✓✓thấy channel để chọn khi đăng
Send Messages✓✓đăng panel, đăng thông báo
Embed Links✓✓gửi được embed, không bị lược thành chữ trơn
Create Invite✓–tạo invite riêng cho từng nguồn
Manage Server✓–đọc số lượt dùng invite → biết ai đến từ nguồn nào
Manage Roles✓–gán role cho người bấm nút đăng ký nhận thông báo

Cộng lại thành mã quyền 268454945 cho server nhà và 19456 cho server đối tác. Dán Client ID vào đây để lấy link mời sẵn:

Mời vào server nhà — chờ Client ID Mời vào server đối tác — chờ Client ID

Manage Roles chỉ hoạt động khi thứ tự role đúng. Vào Server Settings → Roles và kéo role của bot lên trên role thông báo. Role bot nằm dưới thì Discord từ chối với lỗi Missing Permissions — người bấm nút vẫn vào danh sách và vẫn nhận DM, chỉ là không được gán role.

Sau khi mời, lấy ID server nhà: bật Developer Mode trong Discord (Settings → Advanced), chuột phải tên server → Copy Server ID. Đó là HOME_GUILD_ID.

Chạy website

Yêu cầu

Node.js 23.4 trở lên — dự án dùng node:sqlite có sẵn trong Node nên không cần trình biên dịch native. Kiểm tra bằng node -v.

npm install

5

Tài khoản admin

Dashboard không có mật khẩu riêng. Nó đăng nhập bằng Discord, và chỉ những Discord ID khai trong DASHBOARD_OWNER_IDS mới vào được.

  1. Trong Discord: Settings → Advanced → Developer Mode → bật.
  2. Chuột phải avatar của bạn (ở đâu cũng được) → Copy User ID.
  3. Dán vào .env. Nhiều người thì cách nhau bằng dấu phẩy, không có dấu cách:
DASHBOARD_OWNER_IDS=123456789012345678,987654321098765432
  1. Khởi động lại bằng npm start.
  2. Mở dashboard → Đăng nhập với Discord → Authorize.

App chỉ xin quyền identify — đọc tên, ID và avatar của bạn. Nó không đọc email, không đọc tin nhắn, không vào server thay bạn.

Đăng nhập bằng tài khoản chưa được khai thì bạn nhận đúng một trang báo lỗi có sẵn ID cần thêm và bốn bước để sửa — không cần đoán.

Phiên đăng nhập hoạt động thế nào

ViệcCách làm
Phiên lưu ở đâu Cookie growth_session, HttpOnly, SameSite=Lax, ký HMAC-SHA256 bằng SESSION_SECRET, hạn 7 ngày. Cờ Secure tự bật khi PUBLIC_BASE_URL là https://. Server không lưu gì, cookie sửa tay là bị từ chối.
Thêm admin Thêm ID vào DASHBOARD_OWNER_IDS → khởi động lại.
Thu hồi quyền của một người Xoá ID khỏi DASHBOARD_OWNER_IDS → khởi động lại. Mất quyền ngay lập tức dù cookie còn hạn, vì mỗi request đều kiểm tra lại danh sách.
Đăng xuất tất cả mọi người Đổi SESSION_SECRET → khởi động lại. Mọi cookie cũ thành vô hiệu.

Ai đăng nhập được dashboard là gửi được tin nhân danh bot của bạn — đăng vào channel, gửi DM cho người đã đăng ký. Chỉ khai ID của người bạn thật sự tin. Đây cũng là lý do HOST mặc định chỉ nghe 127.0.0.1.

Mở ra internet

Mặc định dashboard chỉ nghe 127.0.0.1 nên chỉ máy bạn vào được. Đó là lựa chọn có chủ ý: dashboard gửi tin nhân danh bot. Nếu vẫn cần mở ra ngoài:

  1. Đặt HTTPS + reverse proxy (Caddy, nginx, Cloudflare Tunnel) trước app.
  2. Đặt HOST=0.0.0.0 để app nhận kết nối từ proxy.
  3. Đặt PUBLIC_BASE_URL thành domain thật, có https://.
  4. Khai thêm redirect URI mới ở Developer Portal: https://domain-cua-ban/api/auth/callback.

Đừng mở cổng 3000 trần ra internet. Không có HTTPS thì session cookie đi ở dạng không mã hoá; ai lấy được cookie đó là điều khiển được bot của bạn. App cũng tự cảnh báo khi PUBLIC_BASE_URL là http:// trên domain ngoài.

Lệnh & sao lưu

npm start        # chạy bot + dashboard
npm run dev      # chạy với watch, tự khởi động lại khi sửa code
npm test         # bộ test
npm run typecheck

Sao lưu data/growth.db trước khi cập nhật code. File đó chứa template, danh sách người đăng ký nhận thông báo, lịch sử đợt gửi và toàn bộ log join — mất là không dựng lại được. Chỉ cần copy file khi app đang tắt.

.env và data/ đã nằm trong .gitignore. Đừng đưa chúng lên git.
